# 安全模型与设计边界

## 核心原则

1. **先确认目标，再执行动作**：目标必须是经名称和发布者判断的消费级产品；MSI 使用系统提供的产品身份核验；EXE 运行前验证可信数字签名。
2. **状态未知不能当成功**：卸载进程返回 0、登记项暂时消失、系统没有列出某个服务，都不等于完成。失败、中断、扫描权限不足都禁止通过验收。
3. **诊断与操作分离**：服务、驱动、计划任务、注册表和 Program Files 保持只读。隔离只涉及白名单内的当前用户数据目录，且必须确认后台组件已消失并经两次确认。
4. **允许恢复，不允许覆盖**：隔离记录先落盘再移动；重启后核对准备/恢复中状态；恢复前重新校验 ID、路径、原目录占用与父级重解析点。
5. **系统边界**：企业/托管安全产品不进入自动卸载范围；不使用内核级自保护绕过技术。

## 已知局限与必须实测项

- EXE Authenticode 使用 从 Windows 系统 API 获取真实 System32 后启动的 Windows PowerShell 系统签名验证；旧版无签名或验证服务不可用时**不会自动执行**，需人工使用官方卸载路径。
- Windows Installer 产品身份来自 `MsiGetProductInfoW`。无法确认的 MSI（例如损坏安装登记或某些用户上下文）会失败关闭。
- 目录隔离借助 `os.Rename`；只有同卷可操作，不保证断电情况下完整的 NTFS 事务原子性，也未解决所有同机多登录会话竞争场景。
- 反向恢复时能校验目录联接点，但源路径与操作之间仍存在需要 Windows 真机故障注入验证的 TOCTOU 竞态；未完成此项前不得宣称安全认证。
- 任务枚举读取 `%WINDIR%\System32\Tasks`，不等于使用 Task Scheduler COM 枚举全部任务；驱动来自 `Services` 注册表登记，不等于真实内核加载状态。
- 部分进程镜像路径由于系统权限不可读；不能把未发现误称为已排除全部服务或驱动。
- 本工具当前覆盖**当前用户**的 AppData 及常见系统位置，不自动跨所有用户分析。
- 诊断日志含本地路径和软件信息；未提供内建脱敏导出。

## 卸载状态规则

`pending -> running -> verified / reboot_pending / blocked / failed`。没有已记录的接受结果、处于 pending/running、失败/受阻或者会话文件损坏的目标**不能判定通过**。当前用户若手动解决失败，需要创建新的卸载尝试记录并重新验证；当前版本没有人工跳过验收按钮。

`范围内通过` 的条件包括：读取无错误、有有效会话、每个目标已登记复核成功、重启已验证、当前检查范围内无已安装目标或其他线索（包括隔离记录）。这**不等于系统全盘零残留**。
